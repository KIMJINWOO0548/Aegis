# 공개 관찰과 신호 추이 범위 적용

2026-11-06 UTC. 기존 120개 메모리 요약의 읽기 흐름을 개선한다. 전체 Grafana 복제나 과거 DB 조회·장비 제어는 범위가 아니다. 사용자의 관련 제품 조사·독자 구현 요청 범위에서 Replica recon/diff를 적용했다.

| 공개 출처 | 직접 관찰 | 독자 적용 |
|---|---|---|
| https://grafana.com/docs/grafana/latest/visualizations/dashboards/use-dashboards/ | REA 6.8.0 실제 브라우저 캡처에서 현재 범위, 상대 범위 선택, 정확한 시작·종료 시각 설명을 확인했다. | 이미 수신·보관된 UI 요약의 전체/30초/60초 범위와 실제 표시된 UTC 끝점을 제공한다. |

S01 공개 문서의 시간 범위 설명. S02 Aegis의 기존 신호 추이. F01 신호 선택 → 범위 선택 → 표시 개수·실제 시각 확인 → 전체 보관 범위로 복귀. 로그인된 Grafana 화면의 실제 클릭·오류·빈 상태는 관찰하지 않았고, 외부 제품과 클릭 수·성능·미관 우열을 비교하지 않는다.

관찰된 패턴은 범위 선택과 시각 맥락의 명시다. Aegis는 최대 120개 요약만 메모리에 보관하므로 임의 DB 과거 범위 선택 대신 마지막 **보관된 타임스탬프** 기준 30/60초로 한정했다. 이 기준에는 기존 transport null 표식도 포함되며 현재 시각이나 추가 원시 조회를 뜻하지 않는다. 수신이 멈춘 이력을 현재 상태로 승격하지 않고 기존 historical 표기를 보존한다. 필터는 보관 배열을 변경하지 않으며 기존 null 단절·수집 품질·기기 분리 규칙을 유지한다.

원본 화면과 DOM은 상위 작업공간 `reference-evidence/grafana`의 로컬 참고 자료이며 제품에 포함하지 않는다. 커밋 대상 `rea-summary.json`에는 실행·정리 상태와 증거 해시만 있다. 제품 코드·브랜드·이미지 자산·사유 API를 복제하지 않았다. Replica pack `77c9436fb3d18c3d58169efb8caf4fe906b0dc51`의 실제 `parity.py` 실행 결과는 `parity.json`이다. 점수는 선정한 구현 패턴만 대상으로 하며 전체 제품 동등성·운영 준비·미관 검증이 아니다. 동등한 두 제품 화면이 없어 screenshot diff는 실행하지 않았다.
