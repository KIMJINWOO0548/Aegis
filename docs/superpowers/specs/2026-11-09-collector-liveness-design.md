# 수집 작업 생존과 모듈 복구

사용자 요청: 살아 있는 무응답 수집기와 내부 수집 작업 종료를 감지하고 해당 모듈만
복구합니다. 정상 무데이터와 구분하고 자동 복구를 제한하며 원본·저장 커서를 보존합니다.
이번 원격 기준은 `improve/numeric-tag-integrity-20261109`의
`bbb0ed10bb43b0aec65d9d0c8d7b79c40b9c4144`입니다.

## 접근과 선택

- 관측 순번/accepted count 정체를 감시하면 정상 빈 replay·중복 자료·최대60초 폴링을
  장애로 오인합니다. 이를 재시작 근거로 사용하지 않습니다.
- 서비스 전체 재시작은 정상 모듈의 저장·평가까지 끊으므로 이번 범위에서 제외합니다.
- 선택: 내부 task/실행 중 poll의 생존 확인과 부모의 유효 요약 수신 watchdog을 분리하고,
  기존 모듈 프로세스·동일 archive 경계에서 유한 복구합니다. 새 의존성과 UI 변경은 없습니다.

## 계약

1. Collector는 task의 정상 반환·예외·뜻밖 취소를 실패로 드러냅니다. 실행 중 poll이
   `max(10초, HTTP timeout×2)`를 넘으면 별도 실패입니다. 정상 폴링 사이 sleep은
   실행 중 poll이 아니며 빈 응답·중복·처리된 timeout도 완료된 시도입니다.
2. module_worker는 생존 확인을 통과한 뒤에만 기존 요약을 발행합니다. 실패한 수집 task를
   정상 heartbeat로 덮지 않고 정리·종료합니다. 실패 코드는 고정 문자열이며 비밀을 출력하지 않습니다.
3. 부모는 동기 설정 전송 완료 후 reader를 등록하고 deadline을 검사합니다.
   기준 시각은 프로세스 시작 또는 마지막 검증된 완전한 요약이며 기본10초입니다.
   무출력·부분 줄·잘못된 frame은 유효 요약이 아닙니다. 원시 관측의 오래됨과 별개입니다.
4. 모듈별 자동 복구는 한 start/stop 수명에서 기본3회(최초 실행과 별도), 지연2초입니다.
   유효 frame 하나나 장시간 정상 실행으로 예산을 자동 초기화하지 않습니다.
   고갈하면 FAILED / WORKER_RECOVERY_EXHAUSTED를 API에 드러내고 멈춥니다.
5. 구 프로세스를 회수하고 reader가 끝났음을 확인한 뒤에만 같은 archive에 다음 writer를
   엽니다. 회수 실패는 FAILED / WORKER_CLEANUP_FAILED이며 추가 launch를 막습니다.
   stop 실패도 숨기지 않습니다. Python은 막힌 OS I/O thread를 강제로 중단할 수 없으므로
   이런 경우 운영자 조치/호스트 재시작이 필요할 수 있습니다.
6. 같은 deterministic archive 경로와 기존 SQLite 원자적 append/cursor를 그대로 사용합니다.
   DB/WAL 삭제·커서 reset/수동 전진·원본 재작성은 하지 않습니다. 동료 모듈은 계속 실행합니다.
7. terminal 실패 후 원인과 구 worker 회수를 확인한 운영자가 명시적으로 stop/start한 경우에만
   새 복구 예산을 시작할 수 있습니다. 살아 있는 구 worker/reader가 있으면 재시작을 거부합니다.

## 범위와 비용

기존 문서가 미구현으로 남긴 watchdog 경계를 확장합니다. 정상 응답이지만 새 자료가
없으면 NO_NEW_DATA 등 기존 연결 사유를 유지하며 프로세스를 재시작하지 않습니다.
실제 장비 프로토콜·Windows 서비스 복구·UI·.NET Gateway/Worker는 이번 범위가 아닙니다.

Ruling: 실패 횟수는 정상 frame에도 자동 초기화하지 않습니다. flapping이 무한 복구로
숨는 것을 막기 위한 선택이며, 수명 중 흩어진 장애3회 뒤에는 운영자 재가동이 필요할 수 있습니다.
Ruling: 실행 중 poll10초 및 요약10초는 프로토타입 기본 경계입니다. 디스크/CPU 부하가
이를 넘으면 정상적으로 느린 작업도 재시작할 수 있으므로 현장값으로 검증한 제한은 아닙니다.
Ruling: 이번 단계는 설정 전달 완료 후의 장애 감시로 한정합니다. 기존 동기 stdin.write/flush에서
읽지 않는 자식과 pipe 용량을 넘는 설정이 만나는 경우 host/peer가 막힐 가능성은 재현·수정하지
않았습니다. 비용은 이 시작 구간의 응답 deadline을 보장하지 못한다는 점이며 후속 검증 대상입니다.

## 증명

내부 task 반환/예외/취소, active poll 정지와 긴 idle 대조군, 정상 무데이터,
무출력/부분 줄, 유한 복구와 frame 후 반복 종료, stop/회수 실패를 시험합니다.
Linux의 실제 소유 worker 정지·복구 시험에서 동료 PID/저장 진행, 원본 prefix/수신 시각,
SQLite integrity/커서/연속성을 확인합니다. 실제 장비·Windows 서비스 결과로 승격하지 않습니다.
기존 시험이 생성하는 고정 경로 evidence는 임시 폴더에 별도 보관하고 기존 바이트를 복원합니다.
