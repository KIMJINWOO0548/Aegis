# 노이즈 속 실제 변화 보존 — 첫 개발 범위

사용자 우선순위는 처리량 경쟁보다 노이즈 속 실제 공정 변화의 보존과 구분이다. 이번 구현은 구분 근거를 수집하는 개발용 흐름이며, 센서 잡음과 실제 고장의 원인을 확정하는 분류기는 아니다.

## 판단 원칙

- 원시 관측값과 원래 quality는 SQLite에 그대로 보존한다. 보간·평활값을 덮어쓰지 않는다.
- 유량의 signed residual(actual−setpoint)에 두 경로를 둔다. 최근 5점의 인과적 중앙값은 분석용 추세로만 제공한다. 원시 residual의 변화는 매 프레임 별도로 검사한다.
- 현재 점을 넣기 전 최근 1초/최대 256점의 중앙값과 MAD로 국소 변동을 기술한다. 5점 이상, 실제 시간 범위 200ms 이상일 때만 문맥을 준비된 것으로 본다. 임계값 max(0.5 L/min, 6×MAD)는 개발 가정이며 실제 장비 보정값이 아니다.
- 임계값을 넘은 첫 점부터 검토 이벤트를 연다. 기준과 임계값을 이벤트 동안 고정하고 이벤트 표본을 다음 후보의 기준 문맥에 넣지 않는다. 지속 변화를 새 정상으로 학습하거나 원래 값으로 돌아오는 것을 새 이상으로 오인하지 않기 위해서다. 장기 이벤트 뒤에는 기준 문맥을 다시 준비한다. 원시 오차의 최소·최대·피크 편차, 시각/원시 observationId, 표본 수와 최대 표본 간격을 남긴다.
- 압력·모터 전류·밸브 피드백의 동시 변화는 근거 목록이다. 공통 전기 노이즈도 여러 센서를 함께 움직일 수 있으므로 실제 공정 현상으로 확정하지 않는다. 이벤트의 disposition은 UNRESOLVED다.
- 유효하지 않은 입력·1.5초 초과 공백·mode/state 변경·앵커 대비 0.5 L/min 이상 설정값 변경은 문맥을 다시 준비한다. 진행 중 이벤트는 중단 사유로 닫으며 공정 복구라고 부르지 않는다. 전환 중 변화는 판단 유보다.
- 최근 이벤트 32개와 누락된 요약 수만 메모리에 유지한다. 원본은 계속 보존한다. 재시작 시 파생 상태는 초기화된다. 이 API는 기존 60초/1Hz EWMA와 독립이며 EWMA 점수/경고 계약을 바꾸지 않는다.

## 연결과 검증

모듈 프로세스가 분석을 소유하고 엄격한 요약 계약으로 통합 프로세스에 전달한다. 인증된 GET `/v1/devices/{id}/signal-review`로 같은 결과를 확인한다. 연결 불가 시 현재 추세는 비우고 기록은 마지막 검토 근거로 남긴다. 이번 범위에 WPF 화면 변경은 없다.

합성 정답·잡음 성분·시나리오 이름은 검증기 내부에만 둔다. 깨끗한 신호, 다양한 노이즈, 1Hz 표본 사이의 유효 범위 100ms dip, 지속 step, drift, 설정값/모드 전환, 결측·공백을 검증한다. 동일 관측값에 다른 원인 정답을 붙였을 때 결과도 동일하게 UNRESOLVED여야 한다. 추세 오차 감소와 이벤트 회수/피크 보존/오검토 빈도를 따로 보고한다. 노이즈 제거율을 실제 공정 판별 정확도로 표현하지 않는다.

실제 장비의 대역폭·정상 변동·센서 지연·레시피별 기준과 원인 라벨이 없으므로 현장 분류 성능은 미검증이다. 짧은 이벤트의 실제 지속시간은 표본 간격보다 세밀하게 추정하지 않는다. 느린 drift는 국소 변화 검출기가 놓칠 수 있으며 기존 setpoint-relative EWMA 경로를 유지한다.
