# Dual stored-record read contract

Base: fcca85fd5e85b5b376e73635bcbb29a36f89eee8. Scope is synthetic, standalone backend read interoperability. Existing raw-v1 writes, HTTP routes, simulator, nullable adapter store, cursors and UI remain compatible. This is separate accessible history, not restoration of unavailable preservation commits.

Raw-v1 requires source run, sequence and observation time plus simulator context. Nullable adapter deliveries cannot truthfully be inserted there. Rejected approaches are fabricated metadata, altering existing tables in place, automatic migration, and opening the adapter writer to perform queries. Selected first step is an opt-in `stored-record-query-1` projection over explicitly configured RAW_V1 and ADAPTER_STORE_V1 stores. Actual write delivery into raw-v1 remains NOT_CONNECTED.

Each record has a namespaced native identity, exact stored original metadata and missing statuses, a separate first host receipt, stored provenance and hierarchy evidence, selected signal presence/quality, and representation-specific hashes. Legacy SIMULATOR is normalized to SYNTHETIC with DECLARED_ONLY evidence; acquisition/access not historically stored are NOT_RECORDED. Adapter provenance comes from validated committed pages, never current configuration. No physical-event deduplication across stores or source acknowledgement is claimed.

Queries require an aware UTC-convertible FIRST_RECEIPT window [from,to), at most one day. Null original timestamps remain queryable without replacement. Every configured store is checked in its own pinned ordinary SQLite read transaction. All schema, original rows, cursor/gap or adapter page/record/receipt/state evidence are validated; any source failure fails the entire result. Per-store snapshots are not a distributed atomic snapshot. Completeness means bounded configured snapshots were read, not source/time coverage. Legacy gap counts are whole-store sequence evidence, not window completeness; adapter gaps are NOT_RECORDED.

Bounds: four explicit distinct physical regular files, 10,000 raw rows per store, inherited adapter 64 pages/1,024 records/32 MiB, 64 returned records, 16 selected signals, 4 MiB output, shared cooperative five seconds/five million SQLite VM steps. Ordinary `mode=ro`, query_only, trusted_schema off preserve logical data without immutable/nolock shortcuts. SQLite may create/update WAL/SHM read metadata; no record DML, migration, checkpoint or journal configuration is issued. Parent-directory hostile replacement and uninterruptible native I/O are outside this first step. Config is bounded 64 KiB nonblocking/no-follow regular JSON. No paths or replay tokens appear in reports/errors.

Validation uses synthetic data: dual-format/null/source distinction, boundaries and quality, restart/failure/retry, pinned WAL snapshots, full failure instead of partial output, exact data preservation and CLI input safety. Extract connection-only adapter validators mechanically, retaining writer's binding and confirmation behavior. No equipment, Windows, production/CI or physical disk exhaustion validation is claimed.

Future write interoperability requires a new negotiated archive schema with nullable original metadata and delivery identities, explicit opt-in migration with verified backups and rollback, and new source coverage contracts. Existing raw-v1 readers must remain available until that migration is approved and validated. This change neither performs that migration nor declares the write blocker solved.
