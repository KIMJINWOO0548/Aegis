# Explicit nullable input archive write contract

Base 02b3722f81a98585e7f46a5197106a5c5915aebc. Independent accessible history, not restricted preservation recovery. No existing raw-v1/adapter-store schema, source, cursor, gap, UI or simulator path is automatically changed, migrated or deleted.

The existing finite-fixture adapter-store-1 is pinned to SYNTHETIC replay, and raw-v1 requires original source time/run/sequence and simulator state. Extending either format silently would change their meaning. Introduce separate `input-archive-1` SQLite storage and `archive-write-1` page contract. Reuse generic AdapterRecord/SourceMetadata/RawSignal validation, retaining canonical producer JSON and exact page wire independently. Null/status originals remain null; host receipt is a separate field. Delivery stream/record IDs/tokens never replace originals.

Each file has one explicit immutable seven-field descriptor: adapterId, adapterVersion1.0, streamId, declaredOrigin SYNTHETIC|DEVICE|UNKNOWN, originEvidence DECLARED_ONLY, acquisitionMethod SOURCE_BUFFER_REPLAY|SNAPSHOT_READ, sourceAccessMode READ_ONLY. A DEVICE declaration is not hardware authentication. Changing descriptor under a file is a conflict. Each page declares archive-write-1 with the same descriptor, afterToken/nextToken/endOfStream and bounded records. Tokens are delivery ordering, not source sequence. Same canonical page is idempotent and preserves first wire/receipt; repeated record ID must retain exact canonical content and stored provenance, otherwise reject the entire page. First receipt is never replaced on retry.

Storage is four strict tables: descriptor/hash, ordered accepted page wire/hash/receipt evidence, canonical original records/hash/first receipt, committed delivery state. Page/new records/cursor/EOF commit atomically in WAL/FULL. Confirm requested page and unchanged precommit prefix/descriptor in a fresh read snapshot before returning LOCAL_ARCHIVE_COMMITTED. COMMIT or confirmation uncertainty fences the object; reopen validates authoritative stored evidence. Precommit failures roll back; no source acknowledgement. Empty terminal pages persist EOF, transient no-data does not advance. Strict appID/version checks refuse old/unknown files before SQLite writer opening. Fresh exclusive0600 create, parent fsync, no artifact cleanup/deletion; initialization interruption may leave a refused preserved file.

Bounded whole-store validation reconstructs all evidence from pages with no external fixture binding. 64 pages,1,024 records,32MiB and cooperative5s/5M VM-step per phase;0.2s busy timeout. This is a minimal bounded archive, not an open-ended production device driver. The connection-only validator owns no connection/transaction or configuration writes.

An opt-in standalone `archive_ingest` synthetic collector validates a finite explicit fixture before opening a target, captures host receipt when its read completes, and uses committed state on resume. Its fixture must declare SYNTHETIC replay; generic DEVICE/UNKNOWN writer semantics are tested only with synthetic objects. No real device/library/network is exercised. Synchronous SQLite commit has no await/executor; production async/native-driver isolation remains future work. CLI summary omits record values/identities/paths/internal tokens and makes no source ACK claim.

The existing stored-record-query-1 gets explicit INPUT_ARCHIVE_V1 kind. Same FIRST_RECEIPT window and fail-whole-result semantics, source-original null/status, descriptor provenance DECLARED_ONLY, namespaced delivery identity, gap evidence NOT_RECORDED. New records can be persisted and then retrieved using the actual common query code, with no migration into raw-v1. Existing RAW_V1 and ADAPTER_STORE_V1 inputs remain supported.

Required evidence: duplicate/conflict/origin-binding, source vs receipt time, failed write rollback/FULL/BUSY, COMMIT before/after uncertainty, restart and actual process crash where feasible, reader corruption rejection, pinned WAL read, real CLI ingest+resume+query, old schema/source bytes preserved. Windows, physical equipment, CI, UI verification, power loss and long-term/high-volume operation are not executed or claimed.
